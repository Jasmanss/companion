Go rest. I've got the build.

Overnight Watch is the second headline feature, next to Visual Review. You say goodnight, Steward watches your Claude Code sessions, deploys and CI, calls you only if something is on fire, and in the morning shows what changed. The brief is docs/briefs/overnight-watch.md.

Everything on this page is a picture of the plan, built from what the app already has. It works, so click around, but it does not call, text or save anything, and the key fields in section 6 are not real.

1. The night in one line

Only things that matter reach your phone. Everything else waits for the report.

What the card does

It never starts by itself. A late-evening nudge ("two sessions are still working, want me to watch?") is an offer, because Go rest is what lets Steward call a phone.

Mac checks. Plugged in or on battery (powerMonitor). It cannot see the lid, so it says so. Try the battery switch on the card: the line changes and Go rest still works, because the user may know better.

Keep awake. One powerSaveBlocker from Go rest to the wake time or "I'm up". Released after, so it never holds the Mac awake by accident.

Practice night. The ladder runs and logs what it would have called and texted, sending nothing. Use it for a week before real calls.

Ends at the wake time, at "I'm up", when the user is back and active at the Mac for a couple of minutes, or at a 12-hour cap.

4. Urgent or waiting

Pick what happens and how the phone answers. The steps are the rules in the brief, run on a made-up clock.

    The rules

    urgentCalls. Not heard by a person: texts at once. Still not back 15 minutes later: calls once more. Then stops.
    waitingOne text, then at most one reminder an hour.
    reportNo phone. Written in the night report.

    Rules that keep it safe

    • Not when you're there. Mac used in the last 5 minutes: no call, screen only.
    • Limits. 3 calls and 8 texts a night (Settings). Same-kind events within 10 minutes become one message.
    • Words only. Project name, kind of event, time. Never a command, path, prompt, file name or URL.
    • Only in the window. Go rest to the wake time.
    • One way. You can't reply or press a key yet (no public address to receive it).
    • Never approves anything. No model calls, no commands except the fixed read-only gh and git ones.
    About "stuck". Steward only hears approvals, notifications, prompts and stops. A slow test run looks exactly like a stuck session. So the recommendation is a text at 45 minutes of silence and a call at 90. The user accepted this.

    How it works

    • When it shows. One island card when you're back at the Mac (or at the wake time). A click opens this.
    • Needed you says what Steward did and what you did next, so a missed call is not a mystery.
    • What changed pulls Visual Review's cards for reviews made after Go rest, with Claude's one-line note from Phase 1b. Without Visual Review's history it lists the sessions only.
    • Gaps come from the Mac's sleep and wake events and from Steward not running. The report says so plainly, even when it makes the night look worse.
    • Counts let you match the Twilio bill (here: 2 calls, 2 texts).
    • Kept for 14 nights in the app's data folder. A Clear button sits next to Visual Review's.

    A quiet night reads "Quiet night. Nothing needed you." with only the sessions that finished and the deploys.

    6. Calls and texts

    Recommendation: Twilio

    Voice and text from one account and one number, plain HTTPS from Steward (the way it already talks to Vercel), and a call can carry its words inline, so no web server is needed. Telnyx, Vonage and Plivo can do the same; only phone.ts would change.

    no new dependency Twilio's npm package is not used. Three endpoints with fetch are enough. Confirmed.

    What it costs

    WhenWhatAbout

    Figures come from Twilio's pages and third-party summaries read on 2026-10-24. Check them in the console; prices change. Set a $5 monthly spend alert there.

    What you create yourself

    No chat does this for you, and no chat ever sees the keys.

    1. A Twilio account at twilio.com, with a card and credit. A trial account only reaches verified numbers and adds a "trial" line.
    2. A US phone number with Voice and SMS.
    3. US text registration (A2P 10DLC, sole proprietor). No company number needed. A US or Canadian mobile gets a one-time code. Review takes days, so start this first. Until it's approved, texts are blocked. Calls are separate: a call to your own phone should work the day the account exists (to confirm on the first test call).
    4. An API key (Console, Account, API keys, Standard). Copy the key SID and the secret; the secret is shown once. A key can be revoked without touching the account.
    5. Your own mobile number, which Steward calls and texts.

    Where the keys go

    Settings → Watch, five fields, typed by you in the app. This is only a picture:

    Account SID
    API key SID
    API secret
    Twilio number
    Your number

    The secret is saved the way the Vercel token is (the macOS keychain through safeStorage). The window only ever learns "saved: yes". It's never logged, never in a report or a text. Steward talks only to api.twilio.com.

    What the messages say

    call"Steward here. The production deploy of my-site failed at 2:14 AM. I have also sent you a text."
    text"Steward: my-site production deploy failed 2:14 AM. Open Steward when you can."
    text"Steward: Claude in my-site is waiting for your OK. 1:05 AM."
    What can be built before the account exists: everything except the last live check. A fake provider and a small local fake of the Twilio endpoints for tests, the ladder with a fake clock, the Settings fields, the Watch, the log, the report, the CI source, stuck detection and the island. Only pressing Test call with real keys needs you. That is why the phone phase comes after three phases that need no account.

    9. Decided

    All six recommendations were accepted on 2026-10-24. Status stays designed: the build waits for its go, after Visual Review 2.

    1. Provider. Twilio.
    2. Stuck. A text at 45 minutes of silence, a call at 90.
    3. While text registration is pending. Calls only. Texts-only events (approvals, the 45-minute stuck text) stay on screen and in the night report, which says "would have texted". Turned on by a Settings switch once registration is approved.
    4. Dependency. No Twilio package, plain fetch.
    5. Order. Visual Review 1b and 2, then Overnight Watch 1 to 3, then 4, then Visual Review 3 and 4.
    6. Off the Mac. The GitHub secrets key is decided when that phase comes.
